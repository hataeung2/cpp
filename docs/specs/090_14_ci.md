# Spec 090-14: CI 도입 (Linux Clang 20 preset, docs gate, 레슨 검사부터)

## 0. Assumptions (please review)

| 1 | **GitHub Actions**, 워크플로 파일 하나 `.github/workflows/ci.yml`. 원격은 이미 GitHub(`origin`)이다 | 다른 CI 서비스 | 저장소가 GitHub에 있고 공개 저장소면 Linux 러너가 무료다. 계정 연결이나 비밀 값이 필요 없다 |

(b) 같은 빌드를 레이블 수만큼 되풀이한다. `--report`의 `report.md` 한 장이 레이블별 결과를 이미 나눠 보여 준다 |

(b) 첫 실행마다 vcpkg 빌드가 몇 분 더 든다. 로컬 WSL도 시스템 패키지를 쓴다 |
| 5 | **Action은 GitHub 자신의 것만**(`actions/checkout`, `actions/upload-artifact`), 전체 커밋 SHA로 고정하고 옆 주석에 버전 태그. `permissions: contents: read`, `concurrency`로 같은 ref의 이전 실행 취소 | 태그(`@v4`)로 고정 | 태그는 옮겨질 수 있다. SHA는 무엇이 도는지 diff로 보인다 |
| 6 | **테스트 리포트를 artifact로 올린다**(`out/test-reports/…`, 실패해도 올림, 보존 14일) | 로그만 | 실패한 테스트의 출력과 `report.md`를 로컬에서처럼 읽을 수 있다 |

## 1. Objective
지금 빌드, 테스트, docs gate는 한 사람의 Windows+WSL 머신에서만 돈다(KI-024). 깨끗한 Ubuntu 24.04에서 같은 명령(`build.py`, `lint_docs.py`)을 push마다 돌려, 로컬 환경에만 있는 것(설치된 패키지, 남은 빌드 디렉터리, 건너뛴 gate)에 기대는 회귀를 병합 전에 보이게 한다. 툴체인 설치를 [linux_build_setup.md](/docs/guides/linux_build_setup.md) 그대로 하므로 그 문서도 매번 확인된다.

## 2. Requirement Details

### 2.1 Public API Surface
none (C++ 코드 변경 없음).

### 2.2 Internal Implementation
- `.github/workflows/ci.yml`
  - `on`: `push` (`main`, `feature/**`), `pull_request`, `workflow_dispatch`.
  - `permissions: contents: read`; `concurrency: { group: ci-${{ github.ref }}, cancel-in-progress: true }`.
  - job `docs` (`ubuntu-24.04`, 시스템 `python3` 3.12 — `tomllib` 필요 3.11+): checkout → `python3 .agent/scripts/lint_docs.py` → `python3 .agent/scripts/test_agent_scripts.py` → `python3 .agent/scripts/sync_skills.py --check`.
  - job `linux-debug` (`ubuntu-24.04`, `timeout-minutes: 60`): checkout → apt 설치(Assumption 4) → Kitware CMake 4 → 버전 출력(`cmake`, `clang++-20`, `clang-scan-deps-20`, `ninja`) → `python3 .agent/scripts/build.py --preset linux-x64-debug --test --report out/test-reports/ci` → `upload-artifact`(`if: always()`).
  - 단계 이름은 영어, 주석은 이 spec 링크 한 줄.
- `.agent/scripts/lint_docs.py`: `DOC_DIRS`에 `.github`. `.yml`이 지금 검사 대상 확장자가 아니면 기계 경로 검사에 `.yml`을 더한다(링크 검사는 Markdown만).
- `.agent/scripts/test_agent_scripts.py`: `.github/` 아래 파일의 기계 경로가 ERROR인 경우 하나.

### 2.3 Platform Specifics
Linux만. Windows MSVC CI는 범위 밖(§6): GitHub 호스트 러너의 Visual Studio가 이 프로젝트의 VS 2026과 같은지 확인이 먼저다.

## 4. Edge Cases
- [x] Thread safety / memory ordering — N/A: 코드 변경 없음. 러너의 코어 수가 로컬과 달라 동시성 테스트가 다르게 돌 수 있다: Assumption 8로 다룬다.
- [x] Resource lifetime / RAII / dangling views — N/A: 코드 변경 없음.
- [x] Platform differences (MSVC vs Clang) — Linux Clang만 CI에, MSVC는 §6.
- [x] Template instantiation / concept constraints — N/A.
- [x] ODR — N/A.
- [x] Undefined behaviour — N/A (sanitizer CI는 §6).
- [x] **러너 환경**: probe `CrashDump`는 `gdb`가 필요 → 설치 목록에 있음. 컨테이너 안이 아니므로 `setarch -R`(TSan)은 이번 범위 밖. 네트워크는 googletest FetchContent 다운로드에 필요하고 러너에 있다.
- [x] **문서만 바꾼 push**: `linux-debug`도 돈다(경로 필터 없음). 경로 필터는 `CMakeLists`·`lesson.toml`이 어디서 바뀌는지 빠뜨리기 쉬워 두지 않는다.
- [x] **포크의 PR**: `contents: read`와 비밀 값 없음으로 안전하다.
- [x] **Windows 줄바꿈**: 체크아웃된 파일의 CRLF가 스크립트를 깨지 않는지 첫 실행으로 확인(AC-4).
