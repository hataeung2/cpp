### `tools/exercises.py` (spec §2.1, §2.2, Assumptions 3–8, 11, 13; §4)
The core (definitions, evaluation, progress) imports neither `lessons` nor `practice`: `lessons.py check` loads it, and `lint_docs.py` loads `lessons.py` under another name, so a top-level import of `lessons` would load a second copy or fail. The CLI imports `lessons`, `practice` and `build.py` inside `main` (same `sys.path` insert as `practice.py`).

- Constants: `FILE = "exercises.toml"`, `PROGRESS_FILE = "practice/progress.json"`, `KEYS` (the allowed keys below), `RULE_KEYS = ("build", "build_expect", "exit", "expect", "forbid", "source")`.
- `@dataclass(frozen=True) class Source: file: str; has: tuple[str, ...]; lacks: tuple[str, ...]`.
- `@dataclass(frozen=True) class Exercise`: `id, title, title_en, build ("ok"|"fail"), build_expect, exit (int | "nonzero" | "any"), expect, forbid, source: tuple[Source, ...], fail_hint, fail_hint_en, hint, hint_en, answer, answer_en` (missing strings = `""`), `line: int` (line of its `id =`); property `kind` = `"auto"` when any key of `RULE_KEYS` was written in the TOML, else `"self"` (keep a `rules_written: bool` field). Defaults: `build = "ok"`, `exit = 0`.
- `@dataclass(frozen=True) class Problem: level ("ERROR"|"WARN"); message; line: int | None`.
- `load(path: Path, files: Mapping[str, str | None] | None = None, readme: str | None = None) -> tuple[list[Exercise], list[Problem]]`:
  - TOML syntax / not UTF-8 → one ERROR, no exercises. Top level other than `exercise` (array of tables) → ERROR.
  - Per exercise ERROR: unknown key; missing `id`/`title`; `id` not `[a-z0-9_]+`; duplicate `id`; wrong types (`build` not `"ok"|"fail"`; `exit` not int / `"nonzero"` / `"any"` (bool is not an int); list keys not lists of strings; `source` not a list of tables with `file` (string) and only `has`/`lacks` lists of strings; strings not strings); a regex that does not compile (`re.error`, message names the key and the pattern); `build = "fail"` together with `exit`, `expect` or `forbid` (they cannot be checked); `build_expect` without `build = "fail"`; `files` given and `source.file` not in it (`not a source of the lesson or a file of a unit it uses`) or mapped to `None` (`ambiguous: a lesson source and a unit file have this name`).
  - WARN: `title_en` missing; `hint` given without `hint_en`; `answer` given without `answer_en`; `fail_hint` without `fail_hint_en`; an `expect`, `build_expect` or `has` pattern that matches the empty string (`re.search(p, "")`); `readme` given and `readme_items(readme)` (numbered items of the `## 연습` section) differs from `exercise_groups(exercises)` (ids that differ only in a trailing `_<one letter>` count once).
  - Exercises with ERRORs are dropped; `load` returns the rest.
- `readme_items(text) -> int | None`: count of lines matching `^\d+\.\s` between `## 연습` and the next `## `; None when there is no such heading.
- `@dataclass(frozen=True) class RunResult: build_ok: bool; build_log: str = ""; ran: bool = False; exit_code: int | None = None; signal: str | None = None; stopped: bool = False; truncated: bool = False; stdout: str = ""` (`stopped`: Stop, or a build or run time limit, or the trace budget).
- `evaluate(exercises, run: RunResult, files: Mapping[str, str | None], modified: bool) -> list[dict]`: auto exercises only, in order; each `{"id", "passed": bool, "checked": bool, "failures": [{"rule", ...params}]}`. Text is LF-normalized and matched line by line with `re.search`. Rules, in this order:
  1. `unmodified` when `modified` is false.
  2. `stopped` → `not_finished`; the build and run rules are not checked.
  3. `build = "fail"`: `build_ok` → `build_fail`; else each `build_expect` pattern without a matching line of `build_log` → `build_expect {pattern}`.
  4. `build = "ok"`: not `build_ok` → `build_ok`; else not `ran` → `not_run`; else `exit`: `"any"` passes; `"nonzero"` passes on a non-zero code or a signal; an int passes on that code without a signal → else `exit {expected, actual}` (`actual` = the code, or the signal name); each `expect` pattern without a matching stdout line → `expect {pattern}`; each `forbid` pattern with a matching line → `forbid {pattern, line}` (first such line). With `truncated`, missing `expect` lines and matching `forbid` lines are not failures: the result gets `checked: false` and one `truncated` entry.
  5. Each `source`: the file's text is `None` → `missing_file {file}`; a `has` pattern without a matching line → `has {file, pattern}`; a `lacks` pattern with a matching line → `lacks {file, pattern, line}`.
  `passed` = no failures and `checked`.
- `message(failure) -> str`: English sentence per rule for the CLI (`MESSAGES` table). The page builds its own text from `rule` and the params (`i18n.ts`).
- `public(exercise) -> dict` for the page: `{id, title, titleEn, kind, hint, hintEn, answer, answerEn, failHint, failHintEn}` (missing → `null`); rules are not sent (spec §2.1).
- Progress (Assumption 8): `class Progress(root)`; one module lock `_LOCK` for every read-modify-write (the runner thread and the server threads share the process; the server's `files.write_lock` guards repo files, which the progress file is not — same guarantee, one lock in the module that owns the file). File `{"version": 1, "lessons": {"<lesson>": {"<id>": {"passed": "<ISO local time, seconds>", "how": "auto"|"self"}}}}`, written with a temp file + `os.replace`; unreadable or wrong shape → renamed `progress.json.broken-<YYYYMMDD-HHMMSS>[-n]` and a new empty record. Methods: `lesson(lesson_id) -> dict[str, dict]`; `record(lesson_id, ids, how) -> list[str]` (adds missing entries only, returns the new ids; an existing pass keeps its time); `set_self(lesson_id, ex_id, done: bool)` (done: add `how: self` if missing; not done: remove the entry only when it is `how: self`); `clear(lesson_id)`; `passed_counts(defs_by_lesson: Mapping[str, list[str]]) -> dict[str, int]` (passes among the current ids only).
- `check_practice(root, lesson_id, lesson_dir: Path, files: Mapping[str, str], run: RunResult) -> dict` (`files`: name → origin repo path, from `lessons.exercise_files`): no `exercises.toml` → `{}`; ERRORs → `{"exercisesError": "<first ERROR>"}`; else read each practice copy (`practice/<origin>`, missing → None), `modified` = any copy's bytes differ from its origin's, `evaluate`, `Progress.record(lesson_id, passed ids, "auto")`, and return `{"exercises": [result + {"new": id in newly recorded}]}`.
- CLI (Assumption 13), exit 0 / 1 / 2 (arguments):
  - `list <lesson>`: table `id  kind  title` (+ progress mark).
  - `check <lesson> --preset <p>`: `practice.Workspace(root).start(lesson)`, `build.py --preset <p> --target practice_<id>` (captured: build log, exit code), run `out/build/<p>/bin/practice/practice_<id>[.exe]` in the practice lesson folder with the lesson's time limit (quick 10 s, long `[run] timeout`), `check_practice`, then a table `id  result  message` (one row per failure). Exit 0 always after a completed check (results are not errors); 1 on a tool error.
  - `verify <lesson> (--preset <p> | --exe <command...>)`: the original program (`--preset`: built with `build.py --target lesson_<id>`; `--exe`: the given command, already built, launcher allowed before the path), run in the lesson folder, `evaluate(…, files = the origin texts, modified=True)`: exit 1 and a line per exercise that passes on the original (Assumption 5), else 0. A lesson without `exercises.toml` → 0.
  - A preset whose platform is not the host (`linux-*` on Windows) → error with the command to use in WSL; the program could not run here.

### `tools/lessons.py` (spec §2.2)
- `exercise_files(catalog, lesson) -> dict[str, str | None]`: lesson source names → `lessons/.../<name>`; then each file of every unit in `resolve_uses(lesson.uses)` (bare file name → its path); a name already present → `None` (ambiguous).
- `check`: for each lesson with `exercises.toml`, `exercises.load(path, exercise_files(...), README.md text)` (module loaded by path once, `sys.modules["exercises"]`), each Problem → `report.add(level, path, message, line)`.
- `index`: each lesson entry gets `"exercises": <number of exercises that load>` (0 without the file).

### `lessons/CMakeLists.txt` (spec §2.2, Assumption 5)
With `ATUGCC_BUILD_TESTS`, `find_package(Python3 3.11 COMPONENTS Interpreter)` once; for an original lesson with `exercises.toml` and Python found: `add_test(NAME lesson.${_id}.exercises_verify COMMAND ${Python3_EXECUTABLE} ${atugcc_SOURCE_DIR}/tools/exercises.py verify ${_id} --exe ${ATUGCC_TEST_LAUNCHER} $<TARGET_FILE:lesson_${_id}>)`, label `lesson`, timeout as the smoke test. The `exercises.toml` path goes into `CMAKE_CONFIGURE_DEPENDS`, so adding the file to a lesson registers the test at the next build.

### Server (spec §2.1, Assumption 7)
- `runner.py`: `exercises = load_module("exercises", ROOT / "tools" / "exercises.py")`. `_build` also returns the joined log (`(build, log)`). `RunManager(..., exercise_check: Callable[[LessonInfo, RunResult], dict] | None = None)`, default `self._check_exercises` (catalog → lesson → `lessons.exercise_files` → `exercises.check_practice`, origin lesson folder). For a practice job, every `done` after a started build (build failed, or the run ended) merges `exercise_check(...)` into the payload: `exercises` (list) or `exercisesError`. `RunResult`: `build_ok`, `build_log`, `ran` = a run was started and did not fail to spawn, `exit_code`, `signal`, `stopped` = Stop, build or run time limit, or trace limit, `truncated`, `stdout` = `outcome.log`. An exception in the check is reported as `exercisesError` (the run's `done` is never lost).
- `server.py`: `GET /api/exercises?lesson=<id>` → `{lesson, exercises: [public…], progress: {...}, error: str | null}` (404 unknown lesson; no file → `exercises: []`); `GET /api/exercises/summary` → `{"<lesson>": <passed count>}` for the lessons with exercises; `POST /api/exercises/self {lesson, id, done: bool}` → 404 unknown lesson or id, 400 for an auto exercise or a non-bool `done`; returns `{progress}`; `POST /api/exercises/clear {lesson}` → `{progress: {}}`.

### Frontend (spec Assumptions 2, 10, 12; AC-3, AC-7)
#### Interfaces (shared by U8–U10)

- `exercises.ts` (U8): pure `exerciseRows(data, results: ExerciseResult[] | null, lang) -> Row[]` (`Row { id; number: string (README number: `1`, `1a`, `1b` for ids ending `_a`, `_b`); title (with fallback flag); kind; status: 'passed' | 'failed' | 'unchecked' | 'none'; passedAt: string | null; messages: string[] (i18n text per failure, then the fail hint); hint, answer (lang with fallback flag) }`: a recorded pass is `passed` even when the last run failed it (Assumption 8), with the last run's messages still shown under it; `failureText(f, lang)`. Class `ExercisesPanel(host, { onSelf(id, done), onClear() })`: `show(data | null, mode)`, `setResults(results | null, error?)`, `render()`; hint and answer each behind a button (sanitized Markdown, `marked` + `DOMPurify` like `readme.ts`), closed again on each `show`; the self exercise has a "했음" checkbox; a top line in original mode (`exercise.originalMode`); `error` shows the load error; "기록 지우기" button.
- `main.ts`, `index.html` (U9): panel tab `<button data-panel="exercises" data-i18n="exercise.tab">` after README and `<div id="panel-exercises" class="panel exercises">`; on lesson select `api.exercises(id)` → panel; on `done` in practice mode `setResults(d.exercises, d.exercisesError)`, reload progress, and a dot on the tab (`.panel-tabs button.has-news`) when any result has `new`, removed when the tab is shown; on load and after each change `api.exerciseSummary()` → `tree.setExerciseProgress(map)`; mode switch re-renders the panel.
- `lessonTree.ts` (U10): `setExerciseProgress(passed: Map<string, number>)`: a `passed/total` badge (`total` = `LessonEntry.exercises`, only when > 0), kept across `render`.
- `i18n.ts` (U10; ko and en): `exercise.tab`, `exercise.auto`, `exercise.self`, `exercise.passed` (`{time}`), `exercise.failed`, `exercise.unchecked`, `exercise.none`, `exercise.hint`, `exercise.answer`, `exercise.selfDone`, `exercise.clear`, `exercise.clearConfirm`, `exercise.originalMode`, `exercise.loadError` (`{error}`), `exercise.none_defined`, `exercise.fallback` (English missing: Korean shown), `exercise.treeTitle` (`{passed}`, `{total}`), and `exercise.fail.<rule>` for `unmodified`, `not_finished`, `build_fail`, `build_ok`, `build_expect`, `not_run`, `exit`, `expect`, `forbid`, `truncated`, `missing_file`, `has`, `lacks` (Assumption 11 sentences).
- `theme.css` (U10): `.exercises` list layout, status colours from existing tokens, `.panel-tabs button.has-news::after` dot, tree badge `.exercise-progress`.
