# Web Playground (local)

The browser side of the lessons in [`lessons/`](../lessons/README.md): pick a lesson, edit its files, Run, and watch the build log, the program's output, the Tracer events, the code-range timings and the Mermaid diagrams arrive while it runs. Specs: [070-02](../docs/specs/070_02_web_playground.md) (page, server), [070-06](../docs/specs/070_06_long_run_timings.md) (long runs, Timings), [070-10](../docs/specs/070_10_lesson_search_i18n.md) (search, Korean/English).

The page builds with a **preset** and has two modes (spec [070-16](../docs/specs/070_16_practice_workspace.md)): **Practice** (the default) edits the lesson's practice copy under the git-ignored `practice/` and builds `practice_<id>`, so exercises never change `lessons/` and can be reset; **Edit original** edits the repository's own files under `lessons/` and builds `lesson_<id>`, for writing lessons. Both work on files VS Code sees too ([lessons/README.md](../lessons/README.md), "연습 공간").

> **Local only.** The server builds and runs whatever the lessons contain. It listens on `127.0.0.1` only, checks `Host` and `Origin`, and accepts request bodies only as `application/json`, so other web sites cannot drive it. Do not put it behind a proxy or bind it to another interface (public use: task 070-05).

## Start
| What | Command |
|---|---|
| Start and open the page | `py -3 tools/playground.py --open` (Linux: `python3`), or VS Code task **Playground: start** |
| Frontend with hot reload | `py -3 tools/playground.py --dev --open` (task **Playground: start (dev)**): the page comes from Vite on `127.0.0.1:5173`, which proxies `/api` to the API server on any free port |
| Another port | `--port 9000`: the page's port in both modes (default 8765, with `--dev` 5173); a busy port moves on to the next of 20 |

`tools/playground.py` runs `npm ci` with the host's Node when `node_modules` is missing or older than `package-lock.json`, and `npm run build` when `web/frontend/dist` is missing or older than its sources, then starts `web/server/server.py`: through `wsl.exe` on Windows (distribution: `ATUGCC_WSL_DISTRO`, else the default), directly on Linux. WSL2 forwards `localhost`, so the Windows browser reaches the server. On Windows the launcher checks this (spec 070-02-02): when it cannot reach the server within 10 s it stops with `error: Windows cannot reach the API server in WSL ...`; run `wsl --shutdown`, then start it again (KI-040).

Requirements: WSL (Windows) or Linux with CMake 4, Ninja, Clang 20 and Python 3.11+ (the same as the `linux-x64-*` presets, [setup](/docs/guides/linux_build_setup.md)); Node.js 20+ on the host for the frontend build. The first Run configures the `linux-x64-playground` preset (about a minute), the first long-profile Run `linux-x64-playground-release`; each first configure downloads GoogleTest into that build directory (a lesson has `gtest = true`, spec 070-15), so it needs the network; later Runs rebuild only the lesson.

## Structure
```text
web/
  server/                 Python 3.11+ standard library only
    server.py             HTTP API, SSE, static files (127.0.0.1)
    runner.py             one job at a time: preset build → run → stream; limits; Stop
    spans.py              span aggregates per (file, line, label, meter): count/total/min/max, sample, p50/p95
    files.py              path checks, read/write, sha conflict detection, line endings
    capture_diagrams.py   regenerates the Mermaid fixture from the seed lessons
    test_server.py        unittest (CTest: PlaygroundServer)
  frontend/               Vite + TypeScript (versions pinned in package.json / package-lock.json)
    src/  main.ts (wiring), api.ts, editor.ts (Monaco tabs, inline span times), lessonTree.ts (tree, filter),
          search.ts (matching), i18n.ts (ko/en dictionaries, every UI string), output.ts + ansi.ts,
          diagrams.ts (+ replay bar), replay.ts (step state), events.ts, timings.ts, readme.ts, diagnostics.ts, practice.ts (mode, copy paths), exercises.ts (exercises panel), theme.css
    test/ vitest (jsdom)
```
The test fixture program for the runner is `tests/playground/playground_fixture.cpp` (a test target, not a lesson).

## API
| Method | Path | Result |
|---|---|---|
| GET | `/api/health` | `{version, preset, releasePreset, compiler}` |
| GET | `/api/lessons` | lesson index of [`tools/lessons.py`](../tools/lessons.py) (`tracks`, `units`, `tags` = the vocabulary of `lessons/tags.toml`) + `problems` (manifest errors). Tracks, lessons and units carry `titleEn`/`summaryEn`, lessons and units `readmeEn` (`null` when missing; 070-10) |
| GET | `/api/files?path=<repo-relative>` | `{path, content, sha, eol, writable}`: `content` always uses LF; `sha` = SHA-256 of the bytes on disk |
| PUT | `/api/files?path=…` `{content, baseSha}` | `{sha}`; 409 `{content, sha}` when the file changed since `baseSha` (`null` = create a new file); 403 outside `lessons/` and the practice copies |
| GET | `/api/practice?lesson=<id>` | the lesson's practice copies after following origin changes: `{lesson, dir, files: [{path, origin, state}], units: [{id, dir, files}]}`, `state` = `same` \| `modified` \| `both` \| `missing-origin` (an unmodified copy whose origin changed has already taken the new origin); 400 without `lesson`, 404 unknown lesson (070-16) |
| POST | `/api/practice/start` `{lesson}` | makes the missing copies (never overwrites one), then the same body as GET; 404 unknown lesson |
| POST | `/api/practice/reset` `{lesson}` \| `{unit}` \| `{path}` | `{reset: [paths], backup: "practice/backup/lessons/<id>" \| "practice/backup/units/<id>" \| null}`; exactly one key, else 400; unknown lesson or unit 404; a path that is not a practice copy 400 |
| GET | `/api/exercises?lesson=<id>` | `{lesson, exercises: [{id, title, titleEn, kind: "auto" \| "self", hint, hintEn, answer, answerEn, failHint, failHintEn}], progress: {<exercise>: {passed: <ISO time>, how: "auto" \| "self"}}, error}` from the lesson's `exercises.toml` (rules are not sent; no file: `exercises: []`; a broken file: `error` set); 400 without `lesson`, 404 unknown lesson (spec [070-17](../docs/specs/070_17_exercise_check.md)) |
| GET | `/api/exercises/summary` | `{<lesson>: <passed count>}` for every lesson with `exercises.toml` (the tree's `2/3`) |
| POST | `/api/exercises/self` `{lesson, id, done}` | marks an observation exercise done (`done: false` removes the mark): `{progress}`; 400 for an automatic exercise or a `done` that is not a bool, 404 unknown lesson or id |
| POST | `/api/exercises/clear` `{lesson}` | removes that lesson's record from `practice/progress.json`: `{progress: {}}` |
| POST | `/api/runs` `{lesson, profileOverride?, spanMeter?, practice?}` | 202 `{runId}`; runs are queued and executed one at a time. `profileOverride`: `quick` or `long`, this run only; `spanMeter`: `wall` or `cpu` (→ `ATUGCC_SPAN_METER`); `practice: true` makes the missing copies, builds `practice_<id>` and runs it in the copy's folder; another value is 400 |
| GET | `/api/runs/<id>/diagrams?tracer=<t>&until=<seq>[&mark=0\|1]` | step replay (spec [070-07](../docs/specs/070_07_diagram_replay.md)): `{tracer, until, parts: [diagram lines]}`, the Mermaid parts of tracer `t` drawn from its events up to `seq` (the C++ tool `atugcc_diagram_replay`; `mark` default 1 = highlight the last event). 404 no run or no such tracer, 409 the run is not finished, 400 bad numbers or a tracer over 5,000 events, 500 `{error}` when the tool is missing, times out or fails |
| GET | `/api/runs/<id>/stream` | Server-Sent Events from the first event of the run (`id:` = event index; `Last-Event-ID` resumes) |
| POST | `/api/runs/<id>/stop` | kills the run's process group; the stream ends with `done{stopped:true}` |

Path rules: repo-relative with `/`; no `..`, `.`, hidden components (`.git`), absolute or drive paths, backslashes, NUL, or symlinks leading out of the repository (400). Writes: existing files under `lessons/`, or new `.cpp`/`.cppm`/`.hpp`/`.md`/`.toml` files there; existing practice copies under `practice/lessons/` except their `lesson.toml` / `unit.toml` (403 otherwise: `practice/state.json`, `practice/backup/`, new files under `practice/`). The server does not know the page's mode; the page keeps `lessons/` tabs read-only in practice mode. A saved file keeps its line ending (CRLF stays CRLF); new files are LF.

Stream events:
| event | data |
|---|---|
| `phase` | `{phase: configure\|build\|run, profile, requested, limitSec, buildType}` (`profile` = this run's, `requested` = the manifest's; `buildType`: `Debug` or `RelWithDebInfo`) |
| `build` | `{text}` configure/build output |
| `stdout`, `stderr` | `{text}` program output, sent at most every 100 ms |
| `trace` | `{events: [...]}` new 020-05 event lines (message, transition, node); `file` made repo-relative. Span lines never appear here |
| `spans` | `{full, rows: [{file, line, label, meter, count, totalNs, minNs, maxNs, p50Ns, p95Ns, hist: {loNs, hiNs, bins[20]}}], spanLines, lagBytes}`: the span keys changed since this stream's last `spans` event, with cumulative values. The batch that ends with `done` carries every key (`full: true`). No `id:` (not part of the replayable event list); a stream that connects late gets every key in its first `spans` event (`full: true` only once the run is done) |
| `done` | `{build: {ok, ms, diagnostics[], timedOut}, run: {exitCode, signal, timedOut, stopped, traceLimit, ms, truncated, diagnostics[]} \| null, diagrams[], replay: {max, tracers: {<tracer>: <event count>}}, skippedTraceLines, stopped}` (`replay`: how many message/transition/node events each tracer wrote; the server keeps up to `max` = 5,000 per tracer for the replay); `run.diagnostics`: GoogleTest failure lines (`<file>:<line>: Failure`) of the program's stdout, same shape as the build's (spec 070-15). A practice run whose build ran also carries `exercises: [{id, passed, checked, new, failures: [{rule, pattern?, file?, line?, expected?, actual?}]}]` for the automatic exercises (`new`: recorded for the first time by this run; `checked: false`: the output was cut off), or `exercisesError` when the definitions could not be read (spec 070-17) |

Limits (the `PROFILES` table in `runner.py`):

| Profile | Build | Run | Output | Trace file | Preset |
|---|---|---|---|---|---|
| `quick` | 120 s | 10 s | 1 MiB each for stdout and stderr | 1 GiB | `linux-x64-playground` (Debug); `[run] build = "release"` → `linux-x64-playground-release` |
| `long` | 180 s | the lesson's `[run] timeout` (300 s default, 1800 s max) | 8 MiB for stdout and stderr together; the page keeps the last 5,000 lines | 1 GiB | `linux-x64-playground-release` (RelWithDebInfo); `[run] build = "debug"` → Debug |

The profile is the manifest's unless the page's **길게 실행** toggle picks the other one for this run (`profileOverride`). Over the trace-file budget the run is stopped (`done.run.traceLimit`): the program keeps writing the file even when the server stops reading it. Closing the page while a lesson runs stops it.

Span timings (spec 070-06 §2.4 has the design record and the alternatives): span lines are not sent one by one. Every 100 ms the server reads the trace file in pieces of at most 4 MiB (more pieces, for up to 250 ms, while it is behind), adds each span to a per-key aggregate (exact count, total, min, max, and a uniform sample of 1,024 durations over the whole run for p50, p95 and the distribution bars) and sends the changed keys as `spans` events. Memory depends on the number of keys, not of spans. When the server falls behind, `lagBytes` says how far and the page shows "집계 지연". Every run gets `ATUGCC_TRACE_FLUSH_MS=100`, so the program flushes its trace at most every 100 ms: after a crash, or while a program that wrote within the last interval stays quiet, the last lines can be missing or late (KI-016).

How a run works: `cmake --preset <preset>` when `.agent/scripts/build.py` would configure (no build directory, an interrupted configure, a preset file newer than the cache, a directory made for another checkout), `cmake --build --preset <preset> --target lesson_<id> atugcc_diagram_replay` (the replay tool is built with the lesson), then `stdbuf -oL -eL out/build/<preset>/bin/lessons/lesson_<id>` in the lesson folder with `ATUGCC_TRACE_OUT` set to a temporary file (read every 100 ms), `ATUGCC_TRACE_FLUSH_MS=100` and, when chosen, `ATUGCC_SPAN_METER`; every `GTEST_*` variable of the server's environment is removed, so a GoogleTest lesson always runs all its tests. Every child runs in its own session and is killed as a group on Stop, on the time limit and after it exits, so what the program starts ends with the run, unless it detaches into a new session itself (`setsid`, KI-015). An ASan-built program gets `verify_asan_link_order=0` in `ASAN_OPTIONS`, since `stdbuf` works through `LD_PRELOAD`.

## Page
The labels below are the Korean ones; in English the page shows the `en` texts of [`i18n.ts`](frontend/src/i18n.ts) (`ⓘ About`, `Run long`, `Meter`, …).
- **ⓘ 소개** (top bar): shows [`lessons/intro.md`](../lessons/intro.md) in the README panel (`lessons/intro.en.md` in English, falling back to `intro.md`; what this page is, library vs lessons, what can be done here; spec [070-08](../docs/specs/070_08_playground_intro.md)). The page opens on it when the URL hash selects no lesson. It is a plain repository file: edit it in VS Code, or in the page by clicking the path above any README or the intro (it opens the file in the editor); no frontend build needed.
- **Column widths and line wrap** (070-19): the bars between sidebar | editor | right panel drag with the mouse or touch, or move 16 px with ←/→ once focused; a double click or Enter restores the default. Minimum widths: sidebar 160 px, editor 360 px, right panel 280 px; a narrower window shrinks the right panel, then the sidebar, and the chosen widths come back when the window grows (`atugcc.layout`; blocked storage: defaults). Below 900 px the page is one column and has no bars. The editor wraps long lines (continued lines indented): `↩` at the end of the tab row or Alt+Z toggles it (`atugcc.wrap.editor`); the Output panel has its own `↩` (`atugcc.wrap.output`): on = `pre-wrap`, off = `pre` with its columns aligned and a horizontal scroll. README, Events, Timings and exercise panels wrap their text and tables, so no panel scrolls sideways; only a wide diagram scrolls inside its card. In a narrow Timings panel the p50, min and max columns (below 840 px of table width), then also file:line, meter and the comparison column (below 600 px) are hidden and shown in the row's ▸ detail.
- Left: tracks and lessons; units with the lessons that use them. ↻ reloads the index (new lesson folders). The tree keeps the selection (lesson or unit) and the groups you collapsed when it is redrawn.
- **Search** (070-10): the box above the tree filters lessons and units as you type. For lessons it matches the id, titles and summaries in both languages, tags with their names and aliases (`lessons/tags.toml`), `uses` (unit ids, `lib:` header paths) and the track title; for units the id, titles, summaries, `files` and `uses`; every word must match (AND), case and Unicode normalization (NFC) are ignored, and the text is literal (no patterns). Tracks with no match are hidden; the line under the box counts the results. `/` jumps to the box (not while typing in the editor or a field), Esc clears it, Enter opens the first lesson; while a Korean IME is composing, Enter and Esc only finish the syllable. ↻ and a language switch keep the query.
- **Language** (070-10): `EN` / `한` in the top bar switches every UI text, the titles and summaries (`title_en`, `summary_en`; a title shown in Korean while in English is greyed), the tag names and the README (`README.en.md` when it exists, else the Korean one with a notice; the intro: `lessons/intro.en.md`). The choice is kept in the browser's storage (`atugcc.lang`); without one the browser's language decides. Editor tabs, a running lesson, Output, Events and Diagrams stay as they are; program output is never translated (lessons print English).
- **Mode** (070-16, top bar): **연습** (Practice, the default) opens the practice copies (`practice/lessons/…`, made when the lesson is opened) and runs `practice_<id>`; tabs of `lessons/` files are 🔒. **원본 편집** (Edit original) opens and saves `lessons/` and runs `lesson_<id>`; the top bar and the tabs get a warning colour. The choice is kept in the browser's storage (`atugcc.mode`; without storage: Practice). Events, diagnostics and Timings point at the copy, so their line links open the copy's tab; Timings compares a practice run with the previous practice run.
- **Practice bar** (above the tabs, practice mode): **↺ 되돌리기** puts the original back into the active copy, **레슨 되돌리기** into every copy of the lesson (units stay); both first list the files that lose their edits and keep them in `practice/backup/lessons/<id>/` (units: `practice/backup/units/<id>/`). **원본과 비교** opens a side-by-side diff (original read-only, the copy editable). A tab whose copy differs from the original is underlined, `⚠` when the original changed too (the bar then says so); the tree marks lessons and units with an edited copy `✎`.
- **연습** tab (070-17, right panel after README): the lesson's exercises from `exercises.toml` in README order (`1`, `1a`, `1b`…), each with its kind (자동 확인 / 스스로 확인), its state (✓ passed with the time, ✗ failed in the last practice Run with the reasons and the `fail_hint`, ? not checked, — not yet), **힌트** and **해설** buttons (sanitized Markdown, hidden until clicked; English falls back to Korean with a notice) and, for observation exercises, a **했음** box. Every practice Run checks the automatic exercises; a recorded pass stays (`practice/progress.json`) when later code fails it, and **기록 지우기** clears the lesson's record. A Run that passes a new exercise puts a dot on the tab. In **원본 편집** mode the tab says exercises are checked in practice mode. The tree shows `passed/total` next to each lesson with exercises.
- Center: Monaco tabs for the lesson's sources and the files of its `uses`. 🔒 = read-only; ● = modified; Ctrl+S saves; Ctrl+Enter or Run saves every modified tab and runs. Compiler diagnostics become markers, and so do the GoogleTest failures of a run (the failed `EXPECT`/`ASSERT` line). There is no test report view (KI-042).
- When the window gets focus again, unmodified tabs reload from disk; a modified tab whose file changed is marked, and saving it asks: reload from disk / overwrite / cancel.
- Top: **길게 실행** (this run's profile; it starts at the manifest's), **측정기** (`wall` = elapsed time, `cpu` = thread CPU time), the phase with its build type and the time left.
- Right: **README** (sanitized Markdown, relative links open inside the page; a lesson's tags above it as chips: a click searches for that tag), **Output** (ANSI colors mapped to the page's tokens), **Diagrams** (Mermaid parts; never below 80 %, wide ones scroll; "전체 크기" opens the natural size), **Events** (seq order; click to highlight the source line), **Timings**.
- **단계 재생** (070-07, Diagrams tab, after the run): the bar above the diagrams switches the replay on (tracer choice when there are two or more, ⏮ ◀ ▶ ⏭, a slider, `k / n` and the event). The diagram is then the one up to that event with the last event highlighted, and earlier Sequence parts are folded. Each step also selects the event's Events row and highlights its source line in the editor; clicking an Events row moves the replay there; ←/→ step while the panel has the focus. A tracer with more than 5,000 events, or whose events the Events tab (first 5,000) does not hold completely, shows the reason instead. Off: the finished diagrams as before.
- **Timings** (070-06): one row per (label, file:line, meter) with count, total, mean, p50, p95, min, max and the change of the mean against the previous run of the same lesson (kept in the browser's storage; "빌드 다름" when the build type differs; the column is empty when storage is blocked). It updates while the run goes and opens by itself at the first span of a run. Click a header to sort, a row to jump to its line, ▸ for the distribution bars. The editor shows `⏱ <mean> avg ×<count>` at the end of each span's start line (rows on one line merged), cleared at the next Run.

| Mermaid fixture | `python3 web/server/capture_diagrams.py` (WSL), after changing a lesson or the diagram generator |
